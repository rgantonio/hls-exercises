### b) The pin register is written on every running cycle with ap_vld high

```

vsum.v:198:      loop_count_preg <= loop_count;
vsum.v:175:  if ((~((1'b1 == ap_CS_fsm_state1) & (ap_start == 1'b0)) & (len_ap_vld == 1'b1))) begin
vsum.v:176:      len_preg <= len;
vecadd_dace.v:150:  if ((~((ap_start == 1'b0) & (1'b1 == ap_CS_fsm_state1)) & (loop_count_ap_vld == 1'b1))) begin
vecadd_dace.v:151:      loop_count_preg <= loop_count;
```

The enable is "not idle, and ap_vld high". It is not limited to the start state: on any cycle of the run where the driver holds `ap_vld` high, `*_preg` reloads from the port. Vitis's ap_vld semantics are "a new value whenever valid is high", not "valid once per run". `ap_block_state1` (vsum.v:425) only makes the start wait for valid.

### c) vsum compares read a mux that forwards the port

```
vsum.v:344:  if ((loop_count_ap_vld == 1'b1)) begin
vsum.v:345:      loop_count_in_sig = loop_count;
vsum.v:347:      loop_count_in_sig = loop_count_preg;
vsum.v:446:  assign icmp_ln14_fu_115_p2 = ((b_fu_68 == loop_count_in_sig) ? 1'b1 : 1'b0);
vsum.v:448:  assign icmp_ln22_1_fu_174_p2 = ((add_ln22_1_fu_120_p2 == loop_count_in_sig) ? 1'b1 : 1'b0);
vsum.v:450:  assign icmp_ln22_fu_169_p2 = ((add_ln22_fu_163_p2 == len_in_sig) ? 1'b1 : 1'b0);
```

`len_in_sig` is the same mux (vsum.v:320-323). The pipelined loop (`ap_ST_fsm_pp0_stage0`) compares against `*_in_sig`. While `ap_vld` is high, that is the raw port through a combinational mux; only while `ap_vld` is low is it `*_preg`. The pin is held only if the driver pulses `ap_vld` for one cycle at start. Driving `ap_vld = ap_start` would not be enough, because under `ap_ctrl_hs` `ap_start` stays high until `ap_ready`.

The DaCe top does hold the bound. `loop_count_in_sig` feeds `N_fu_55_p3`, which is registered only in the start state, and the sub-pipeline's compare reads that register's descendant:
