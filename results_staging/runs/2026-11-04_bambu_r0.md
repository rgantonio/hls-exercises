# Bambu RTL-only flow, one point (BAM2 R0), 2026-11-04

vecadd W = 8 at 10 ns, case `bambu` (Bambu's default setup plus `#pragma HLS unroll` on LANE), run on the server with `bench/bambu.py`. Bambu builds the RTL once at n512 in the podman container, without `--simulate`. Our SystemVerilog testbench (tb/vecadd_tb.sv) then simulates it in Questa on the host, at n64 and n512: a no-stall run for cycles and a random-stall run with two tasks for pass/fail. Code at 932b56e. The build tree was wiped (`rm -rf build`) before the run.

## Commands

```bash
git pull                       # main at 932b56e
rm -rf build
podman image exists localhost/hls-exercises-bambu:4   # exists; tools/bin/bambu present
lmutil lmstat -a -c 1717@licserv                      # msimhdlsim: 75 issued, 1 in use
pixi run python bench/bambu.py run --kernel vecadd --w 8 --dry-run
pixi run python bench/bambu.py run --kernel vecadd --w 8 -j32 --sim questa --sim-jobs 2
```

Bambu command (from `rtl/done/vecadd/bambu_w8/cmd.txt`): `bench/tools/in_bambu.sh bambu vecadd.cpp --top-fname=vecadd --device-name=nangate45 --clock-period=10 --compiler=I386_CLANG16 --generate-interface=INFER -DDATA_T=int64_t -DSIZE_N=512 -DBAMBU_LANES=8 --std=c++14 -Ibench/include/bambu -Ibench/tier_done/vecadd/src -Ibench/tier_done/vecadd/vectors/n512`. Each simulation runs `vlog -sv` on tb/vecadd_tb.sv and the point's vecadd.v (with `+define+DUT=_Z6vecaddPK6ac_intILi512ELb0EES2_PS0_j`, W, N, NOUT, STALL, MAXCYC, LOOP_COUNT), then `vsim -c tb`.

## Unexpected

- Each Questa run gives 2 warnings, the same in all four: `vecadd.v(1811): (vopt-2685) [TFMPC] - Too few port connections for 'fu__Z6vecaddPK6ac_intILi512ELb0EES2_PS0_j_428532_429248'. Expected 11, found 10.` and `(vopt-2718) Missing connection for port 'out1'`. The instance is Bambu's `C_bambu_artificial_ParmMgr_Write_axis_modgen` (the axis write of C): Bambu leaves its `out1` output unconnected. BAM1's Verilog has the same instance (the diff above leaves it unchanged), so this is Bambu's output, not part of the new flow. It is harmless for simulation. Synthesis may report it as an unconnected output.
- `rtl/done/vecadd/bambu_w8/` now holds `cmd.txt` next to `filelist.f`, `sizes.txt` and `vecadd.v`. BAM1's `bambu_opt_w8/` has no `cmd.txt`.
- Untracked `rtl/done/vecadd/opt_w8_c10/` and `rtl/done/vecmul/opt_w8_c10/` were already in the working tree before this round. They are left untouched and not committed.
